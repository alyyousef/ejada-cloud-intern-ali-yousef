# Step 1 — Manual OCI Console Build (Lab 2)

Do this before touching Terraform again. The point isn't to produce something permanent —
you'll destroy all of it at the end of this walkthrough — the point is to click through
every required argument on every resource yourself, especially the load balancer, so the
Terraform code you already have stops being "code that happened to work" and becomes "code
that does the thing I already understand."

Use compartment `intern-02-ali-youssef-cmp`, region **Saudi Arabia West (Jeddah)**
(`me-jeddah-1`) — same as always. Prefix every display name with `explore-` (e.g.
`explore-vcn`, `explore-lb`) instead of `tf-lab-*`, so nothing you build here is visually
confused with what Terraform manages, even though OCI doesn't actually care about name
collisions.

Don't use the VCN Wizard / "VCN with Internet Connectivity" quick-create option. It builds
several resources at once and hides exactly the steps you're here to see. Build each piece
separately with **Create VCN Only**, then add each thing under it by hand.

---

## Phase 1 — Networking foundation

### 1.1 VCN

Networking → Virtual Cloud Networks → **Create VCN**.

- Name: `explore-vcn`
- Create VCN Only (not the wizard)
- IPv4 CIDR Block: `10.1.0.0/16`
- DNS label: `explorevcn`

Notice OCI creates a **default route table**, **default security list**, and **default DHCP
options** automatically even in "VCN only" mode — these exist whether or not you ever attach
a subnet to them. You will not use the defaults; you'll make your own route tables and
security lists next so you see those resources created explicitly, matching what
`oci_core_route_table` and `oci_core_security_list` do in `main.tf`.

### 1.2 Internet Gateway

Inside the VCN → Gateways tab → **Internet Gateway** → Create Internet Gateway.

- Name: `explore-igw`

This is the resource `oci_core_internet_gateway.terraform_igw` maps to. Note it has almost
no arguments — just a name and enabled/disabled — the real behavior comes from wiring it
into a route table next.

### 1.3 NAT Gateway

Same Gateways tab → **NAT Gateway** → Create NAT Gateway.

- Name: `explore-nat`

Notice OCI assigns it a public IP automatically — you don't pick one. That's the IP your
private instance's outbound traffic will appear to come from later.

### 1.4 Route tables

VCN → Route Tables → **Create Route Table**, twice:

**explore-public-rt**
- Rule: Destination `0.0.0.0/0` → Target Type: Internet Gateway → target: `explore-igw`

**explore-private-rt**
- Rule: Destination `0.0.0.0/0` → Target Type: NAT Gateway → target: `explore-nat`

This is the exact pair `oci_core_route_table.public_route_table` /
`oci_core_route_table.private_route_table` represent. Same rule shape
(`0.0.0.0/0 → gateway`) on both — the only difference is which gateway, and that
difference alone is what makes one subnet public and the other private.

### 1.5 Security lists

VCN → Security Lists → **Create Security List**, twice.

**explore-public-sl** — ingress rules:
| Stateless | Source | IP Protocol | Destination Port |
|---|---|---|---|
| No | 0.0.0.0/0 | TCP | 80 |

Egress: leave the default (`0.0.0.0/0`, all protocols).

**explore-private-sl** — ingress rules (add all five):
| Stateless | Source | IP Protocol | Destination Port |
|---|---|---|---|
| No | 10.1.1.0/24 | TCP | 8080 |
| No | 10.1.0.0/16 | TCP | 22 |
| No | 10.1.0.0/16 | TCP | 111 |
| No | 10.1.0.0/16 | UDP | 111 |
| No | 10.1.0.0/16 | TCP | 2048-2050 |
| No | 10.1.0.0/16 | UDP | 2048-2050 |

Egress: leave the default.

This is the exact rule set from `variables.tf`'s `public_ingress_rules` /
`private_ingress_rules`, hand-typed instead of generated by the dynamic block. Typing it out
once is exactly what makes the dynamic block in Part B click — you're doing by hand the
thing that block does for you six times over.

### 1.6 Subnets

VCN → Subnets → **Create Subnet**, twice.

**explore-public-subnet**
- CIDR: `10.1.1.0/24`
- Route Table: `explore-public-rt`
- Subnet Access: **Public Subnet**
- Security List: `explore-public-sl`
- DNS label: `public`

**explore-private-subnet**
- CIDR: `10.1.2.0/24`
- Route Table: `explore-private-rt`
- Subnet Access: **Private Subnet**
- Security List: `explore-private-sl`
- DNS label: `private`

Watch the "Subnet Access" toggle specifically — that's the console-level equivalent of
`prohibit_public_ip_on_vnic` in `oci_core_subnet.tier`. Picking "Private Subnet" here is
what makes it structurally impossible to launch an instance in this subnet with a public IP,
later, even if you forget.

## Phase 2 — Compute instance

Compute → Instances → **Create Instance**.

- Name: `explore-linux`
- Image: Oracle Linux 9 (change image if it defaults to something else)
- Shape: whatever your Week 1 instance used (`VM.Standard.E2.1.Micro` if on Always Free)
- Networking: select `explore-vcn` → `explore-private-subnet`
- **Uncheck "Assign a public IPv4 address"** — this is the one checkbox that matters most
  here; if you leave it checked, you've built a public instance and nothing downstream in
  this walkthrough proves anything.
- SSH key: paste the same public key you've used all along (`oci_vm.pub`)

Launch it, wait for **Running**, and note its **Private IP** from the instance details page
— you'll need it twice: once for the load balancer's backend, once for SSH.

You now have no way to reach this box directly — no public IP exists to SSH to. That's the
same wall the real `tf-lab-linux-AliYousef` instance has, and it's why Part A spends a whole
section on Bastion. Create a session now to get in:

Identity & Security → Bastion → **Create Bastion**:
- Name: `explore-bastion`
- Target Subnet: `explore-private-subnet`
- Max session TTL: 3 hours (or leave default)

Then, on the Bastion's detail page → **Create Session** → **Managed SSH Session**:
- Target: your instance's OCID (copy it from the instance details page)
- Target Port: 22
- SSH public key: same key again

OCI hands you back an `ssh -i ... -o ProxyCommand="ssh ..." opc@...` command. Run it from
your terminal to confirm you can actually reach the instance. This is the thing
`bastion.tf` documents but — as you now know from the teardown — was never actually applied
for real, so this is your first time doing it live. Worth taking a moment to actually feel
what it's like: no port ever opened to the internet, a session that expires on its own,
and a full audit trail in the console the whole time.

## Phase 3 — File Storage

Storage → File Storage → File Systems → **Create File System**.

Use the non-wizard "Create in Compartment" path so you see the three pieces separately
instead of one bundled flow:

1. **File System**: name `explore-fs`, availability domain matching your instance's AD.
2. **Mount Target**: name `explore-mount-target`, subnet `explore-private-subnet`. Note the
   private IP OCI assigns it — this is the same value `mount_target_ip_address` reports from
   Terraform.
3. **Export**: path `/explore-export` (must start with `/`), pointing at `explore-fs`
   through the mount target's export set.

Back in your SSH session on `explore-linux`:

```bash
sudo mkdir -p /mnt/appdata
sudo mount -t nfs <mount_target_private_ip>:/explore-export /mnt/appdata
df -h /mnt/appdata   # confirm it's actually mounted, not just silently failed
```

Then seed a page and start something to serve it, so there's a real running application —
matching requirement 2/3 of the assignment:

```bash
sudo tee /mnt/appdata/index.html <<'HTML'
<html><body><h1>Manual console build - explore-linux</h1></body></html>
HTML
sudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload
cd /mnt/appdata && sudo python3 -m http.server 8080 &
```

(A background `&` job is fine for this exploration — it doesn't need to survive a reboot
the way the real systemd service in `app_userdata.sh.tftpl` does.)

## Phase 4 — Load balancer

This is the piece your team explicitly called out. Networking → Load Balancers →
**Create Load Balancer**.

**Basic Information:**
- Name: `explore-lb`
- Visibility: **Public**
- Shape: **Flexible**, min/max bandwidth 10/10 Mbps

**Choose Networking:**
- VCN: `explore-vcn`
- Subnet: `explore-public-subnet` (only one subnet needed for a regional/AD-flexible
  deployment on a single subnet)

**Add Backends** — this step *is* the backend set, even though the wizard doesn't label it
that way:
- Backend set name: `explore-backend-set`
- Policy: Round Robin
- Add the private instance `explore-linux` as a backend, port `8080`
- Health check: Protocol HTTP, URL Path `/`, Port `8080`, Expected status code `200`,
  interval 10000 ms, retries 3

**Configure Listener:**
- Name: `explore-listener`
- Protocol: HTTP, Port `80`
- Default backend set: `explore-backend-set`

Create it. Wait for the load balancer to go **Active**, then check the backend set's health
— it may show **Critical** for a minute or two right after creation while the health checker
runs its first few probes; that's expected, not a failure (you saw the same thing happen on
the Terraform-built version).

Once the backend shows healthy (or even before, since the app itself is already running):

```bash
curl http://<load_balancer_public_ip>
```

You should get back the `index.html` you wrote in Phase 3, having gone client → internet →
listener → backend set → health-checked backend → your instance → the file mounted from
OCI File Storage. That full path is Requirement 1-3 of the assignment, built once by hand.

## Phase 5 — Tear it all down

Destroy in this order — mostly dependency-driven, OCI will refuse a step if something still
depends on it, which is itself useful to see:

1. Load balancer (`explore-lb`) — deletes the listener/backend set with it
2. Bastion sessions expire on their own; delete the Bastion resource itself
   (`explore-bastion`)
3. Compute instance (`explore-linux`) — terminate, and choose to also delete the boot volume
4. File Storage: export → mount target → file system, in that order
5. Subnets (both)
6. NAT Gateway and Internet Gateway
7. Route tables (both)
8. Security lists (both)
9. VCN (`explore-vcn`) last — OCI won't let you delete it while anything above still
   references it, which is a good sanity check that you actually got the order right

Confirm the compartment is empty afterward the same way you did after the Terraform
teardown: Resource Explorer, filtered to `intern-02-ali-youssef-cmp` and Saudi Arabia West
(Jeddah), should show nothing billable left over.
